# 2026 Timeline

This file includes 10 notable incidents, disclosures, and vulnerability-driven milestones relevant to LLM security in 2026 through April 2026.

## Entries

### 41. January 2026: CAI argument injection issue disclosed

- **Category:** Agent CLI security
- **Class:** CVE-backed vulnerability
- **Summary:** Argument handling in an AI agent tooling context created a path for injection and unsafe command behavior.
- **CVE:** [CVE-2026-25130](https://nvd.nist.gov/vuln/detail/CVE-2026-25130)
- **Lesson:** Agent shells and CLI wrappers need explicit argument sanitization and execution policy.

### 42. January 2026: vLLM multimodal denial-of-service issue disclosed

- **Category:** Inference serving security
- **Class:** CVE-backed vulnerability
- **Summary:** Crafted multimodal inputs could trigger denial-of-service conditions in serving paths.
- **CVE:** [CVE-2026-22773](https://nvd.nist.gov/vuln/detail/CVE-2026-22773)
- **Lesson:** Multimodal endpoints expand parser and resource exhaustion risk.

### 43. February 2026: Crawl4AI Docker API hooks remote code execution disclosed

- **Category:** Crawling and retrieval tooling security
- **Class:** CVE-backed vulnerability
- **Summary:** A hooks parameter accepted executable Python in certain deployments, enabling unauthenticated remote code execution.
- **CVE:** [CVE-2026-26216](https://nvd.nist.gov/vuln/detail/CVE-2026-26216)
- **Lesson:** AI-adjacent crawler and ingestion services can become direct server compromise paths.

### 44. February 2026: Enclave sandbox escape issue disclosed

- **Category:** Runtime isolation
- **Class:** CVE-backed vulnerability
- **Summary:** A sandbox escape finding showed that isolation layers for agentic or coding workflows must be treated as primary security controls.
- **CVE:** [CVE-2026-27597](https://nvd.nist.gov/vuln/detail/CVE-2026-27597)
- **Lesson:** Sandboxing promises are only as strong as the isolation implementation.

### 45. March 2026: LangSmith Studio token leak via base URL handling disclosed

- **Category:** Developer tooling security
- **Class:** CVE-backed vulnerability
- **Summary:** Studio tooling for LLM development exposed token leakage risk through configuration or URL handling paths.
- **CVE:** [CVE-2026-25750](https://nvd.nist.gov/vuln/detail/CVE-2026-25750)
- **Lesson:** Developer tooling around LLM systems can leak secrets even when core inference paths are locked down.

### 46. March 31, 2026: Mercor confirmed a cyberattack tied to the LiteLLM supply-chain compromise

- **Category:** AI supply chain security
- **Class:** Public incident under investigation
- **Summary:** Mercor said it was "one of thousands of companies" affected by the LiteLLM compromise. Public reporting said alleged sample data included Slack references, ticketing material, and videos purportedly showing conversations between Mercor systems and contractors.
- **CVE:** None public for Mercor specifically; related to the broader LiteLLM compromise path
- **Lesson:** A compromise in a widely used AI gateway or dependency can rapidly cascade into downstream customer and contractor exposure.

### 47. March 2026: Cross-modal leakage reviews broadened AI data inventories

- **Category:** Multimodal security
- **Class:** Operational trend
- **Summary:** Security programs increasingly cataloged transcripts, embeddings, summaries, and OCR outputs as sensitive derived data.
- **CVE:** None public
- **Lesson:** Derived artifacts belong in the same data protection model as their source assets.

### 48. March 2026: Runtime isolation became a default recommendation for agent workers

- **Category:** Secure architecture
- **Class:** Defensive milestone
- **Summary:** Best-practice guidance converged on isolating agent runtimes, retrievers, and tool workers into separate trust zones.
- **CVE:** None public
- **Lesson:** Blast-radius reduction matters more than assuming perfect model obedience.

### 49. April 2026: Browser and desktop agent approval bypass research accelerated

- **Category:** Agent security
- **Class:** Red-team trend
- **Summary:** Researchers continued demonstrating that agents interacting with browsers or desktops could be nudged around approval UX and trust assumptions.
- **CVE:** None public
- **Lesson:** Human approvals need context, replay resistance, and action-level policy checks.

### 50. April 2026: Memory poisoning persistence studies highlighted long-lived agent risk

- **Category:** Memory security
- **Class:** Research trend
- **Summary:** Long-lived memory stores were shown to preserve attacker influence across sessions when memory hygiene was weak.
- **CVE:** None public
- **Lesson:** Persistent memory is untrusted state unless validated and bounded.
